## 1. 项目概述

### 1.1 项目背景

随着全球竞技体育与群众体育的快速发展，体育赛事信息化已成为趋势。然而在基层及高校层面，比赛数据管理仍存在以下痛点：

- **实时性差**: 从得分到观众大屏平均延迟 30-120 秒
- **通用性弱**: 不同球类规则差异大，现有商业软件功能过度、费用过高
- **数据封闭**: 无法与教务、学籍、省赛报名系统自动对接

### 1.2 项目目标

构建一套"低成本、跨球类、毫秒级、可扩展、开源"的"端-边-云"一体化成绩统计与显示管理系统。

#### 核心目标

| 目标 | 指标 | 说明 |
|------|------|------|
| G1 | 4球类通用 | 支持篮球、排球、羽毛球、乒乓球，38种规则秒级切换 |
| G2 | ≤200ms延迟 | WebSocket+MQTT双协议，端到端实时数据链 |
| G3 | ≤1200元/套 | 硬件BOM成本控制，10×5cm四层PCB |
| G4 | 数据互通 | 符合国标GB/T 34311-2017及CUSU标准 |
| G5 | 开源教学 | 完整开放硬件、固件、Docker镜像 |

### 1.3 系统特色

- **跨球类规则引擎**: 基于BGEMM元模型+Lua脚本热插拔
- **毫秒级实时性**: 双协议融合总线，零拷贝优化
- **离线容错**: 本地SQLite+云端InfluxDB双重保障
- **开源生态**: MIT协议，完整教学资源

### 2.2 技术架构

#### 2.2.1 终端设备层

- **主控**: ESP32-S3 (Xtensa双核240MHz)
- **操作系统**: FreeRTOS 10.5
- **规则引擎**: Lua 5.4虚拟机
- **通信**: BLE 5.0 + Wi-Fi 802.11n
- **显示**: 4.3寸电容触摸屏 (800×480)
- **副屏**: 电子墨水屏 (低功耗待机)

#### 2.2.2 边缘网关层

- **硬件**: 树莓派4B 8GB
- **操作系统**: Ubuntu 22.04 LTS (Arm64)
- **容器化**: Docker 24.0 + Docker Compose
- **实时总线**: Netty 4.1 (主从Reactor模型)
- **缓存**: Redis 7.2
- **离线存储**: SQLite 3 (WAL模式)

#### 2.2.3 云端服务层

- **后端**: SpringBoot 3.2 + JDK 17
- **前端**: Vue3 + Vite + PWA
- **数据库**: InfluxDB 2.7 (时序) + MySQL 8.0 (关系)
- **对象存储**: MinIO
- **监控**: Prometheus + Grafana

## 5. 数据库设计

### 5.1 InfluxDB 时序数据设计

#### 5.1.1 Measurement设计

```
赛事事件: match_events
Tags:
  - match_id: 赛事ID
  - event_type: 事件类型(得分/犯规/暂停)
  - team_id: 球队ID
  - player_id: 球员ID
Fields:
  - value: 分值/参数
  - quarter: 节次/局数
  - timestamp: 时间戳
```

#### 5.1.2 查询示例

```sql
-- 查询某赛事所有得分事件
SELECT * FROM match_events
WHERE match_id='match_001' AND event_type='得分'
ORDER BY time DESC

-- 查询某球员技术统计
SELECT player_id, COUNT(value) as total_score
FROM match_events
WHERE match_id='match_001' AND player_id='player_123'
GROUP BY player_id
```

### 5.2 MySQL 关系数据设计

#### 5.2.1 ER图

```
┌─────────────┐       ┌─────────────┐       ┌─────────────┐
│   teams     │───────│   matches   │───────│   events    │
│             │1    N │             │1    N │             │
│ - id        │       │ - id        │       │ - id        │
│ - name      │       │ - home_team │       │ - match_id  │
│ - players   │       │ - guest_team│       │ - type      │
└─────────────┘       │ - status    │       │ - value     │
                      └─────────────┘       └─────────────┘
```

#### 5.2.2 表结构

**teams表**:
```sql
CREATE TABLE teams (
    id VARCHAR(50) PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    logo_url VARCHAR(255),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**matches表**:
```sql
CREATE TABLE matches (
    id VARCHAR(50) PRIMARY KEY,
    home_team_id VARCHAR(50),
    guest_team_id VARCHAR(50),
    sport_type ENUM('basketball', 'volleyball', 'badminton', 'pingpong'),
    match_time DATETIME,
    venue VARCHAR(100),
    status ENUM('pending', 'ongoing', 'finished'),
    FOREIGN KEY (home_team_id) REFERENCES teams(id),
    FOREIGN KEY (guest_team_id) REFERENCES teams(id)
);
```

**events表**:
```sql
CREATE TABLE events (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    match_id VARCHAR(50),
    event_type ENUM('score', 'foul', 'timeout', 'substitution'),
    team_id VARCHAR(50),
    player_id VARCHAR(50),
    value INT,
    quarter INT,
    event_time DATETIME,
    FOREIGN KEY (match_id) REFERENCES matches(id)
);
```

### 5.3 SQLite 离线存储设计

```sql
-- 本地事件缓存表
CREATE TABLE offline_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    event_data TEXT NOT NULL,  -- JSON格式
    synced INTEGER DEFAULT 0,   -- 0:未同步, 1:已同步
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 本地规则缓存表
CREATE TABLE rule_cache (
    sport_type TEXT PRIMARY KEY,
    rule_content TEXT NOT NULL,  -- Lua脚本内容
    version TEXT,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
