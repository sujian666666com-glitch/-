# Intent: BRSMS MVP Demo

## Problem Statement

根据《开发文档.md》，BRSMS 是一套"端-边-云"一体化成绩统计与显示管理系统，完整实现需要：
- ESP32-S3 终端设备
- 树莓派边缘网关
- SpringBoot + Vue3 + InfluxDB 云端服务

**问题**：完整系统复杂度高，开发周期长，难以快速验证核心架构和演示给指导老师。

## Proposed Solution

构建一个**本地最小可运行 Demo**，简化架构但仍保留核心特性：

```
┌─────────────────────────────────────────────────────────────┐
│                      本地 Demo 架构                          │
│                                                              │
│  ┌───────────────┐    WebSocket    ┌───────────────┐       │
│  │   Vue3 前端   │ ←─────────────→ │ SpringBoot    │       │
│  │   (大屏显示)  │                 │   后端服务    │       │
│  └───────────────┘                 └───────┬───────┘       │
│                                            │                │
│                                            ↓                │
│                                    ┌───────────────┐       │
│                                    │   SQLite      │       │
│                                    │   (本地存储)  │       │
│                                    └───────────────┘       │
└─────────────────────────────────────────────────────────────┘
```

## Success Criteria

| Criteria | Measurement |
|----------|-------------|
| 功能完整性 | 篮球计分、实时推送、大屏显示可正常运行 |
| 实时性 | WebSocket 延迟 ≤ 200ms |
| 可演示性 | 一键启动，无需外部依赖 |
| 代码质量 | 符合开发文档中的代码规范 |

## Alternatives Considered

### 方案 A: 完整架构实现
- **优点**: 符合设计文档
- **缺点**: 周期长，需要硬件设备

### 方案 B: 仅前端原型
- **优点**: 快速
- **缺点**: 无法验证后端架构

### 方案 C: MVP Demo（推荐）
- **优点**: 平衡速度与完整性
- **缺点**: 需要后续扩展
